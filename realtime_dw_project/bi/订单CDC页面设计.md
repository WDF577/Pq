# Power BI 订单 CDC 页面实现说明

当前 PBIP 已保留原有“实时经营总览”，并实现“订单生命周期”和“SCD2 版本审计”两页。数据源 SQL 见 `order_cdc_queries.sql`，报表入口为 `电商实时数仓运营看板.pbip`。

## 页面目标

让业务人员回答：各渠道有多少订单、支付和退款表现怎样、净支付金额如何变化；让面试官看到 CDC 更新流和 SCD2 不只停留在后端表里。

## 页面布局（16:9）

```text
┌──────────────────────────────────────────────────────────────┐
│ 订单生命周期                                      日期  渠道 │
├──────────┬──────────┬──────────┬──────────┬─────────────────┤
│ 总订单数 │ 支付订单 │ 支付率   │ 退款率   │ 净支付金额      │
├───────────────────────────────┬──────────────────────────────┤
│ 每日支付/退款金额趋势          │ 渠道订单状态（分组柱状图）   │
├───────────────────────────────┼──────────────────────────────┤
│ 渠道净支付金额                 │ 渠道明细矩阵                  │
└───────────────────────────────┴──────────────────────────────┘
```

不要把取消看成漏斗后续阶段：取消与支付是 CREATED 后的分支，适合分组柱状图，不适合强行画成单调漏斗。

## 已实现 DAX

Import 表命名为 `订单每日指标`，源值列在报表字段列表中隐藏；页面使用以下显式度量：

```DAX
总订单数 = COALESCE(SUM('订单每日指标'[总订单数值]), 0)
支付订单数 = COALESCE(SUM('订单每日指标'[支付订单数值]), 0)
取消订单数 = COALESCE(SUM('订单每日指标'[取消订单数值]), 0)
退款订单数 = COALESCE(SUM('订单每日指标'[退款订单数值]), 0)
支付金额 = COALESCE(SUM('订单每日指标'[支付金额值]), 0)
退款金额 = COALESCE(SUM('订单每日指标'[退款金额值]), 0)
净支付金额 = [支付金额] - [退款金额]
支付率 = DIVIDE([支付订单数], [总订单数])
退款率 = DIVIDE([退款订单数], [支付订单数])
支付客单价 = DIVIDE([支付金额], [支付订单数])
```

格式：订单数使用 `#,##0`，金额使用 `¥#,##0.00`，比例使用 `0.0%`。

## 视觉映射

| 视觉 | 轴/字段 | 值 |
| --- | --- | --- |
| 日期切片器 | `订单日期[订单日期]` | Between |
| 渠道切片器 | `渠道[渠道]` | 下拉多选 |
| 金额趋势 | X=`订单日期[订单日期]` | 支付金额、退款金额 |
| 状态分组柱状图 | X=`渠道[渠道]` | 支付订单数、取消订单数、退款订单数 |
| 渠道净支付柱状图 | X=`渠道[渠道]` | 净支付金额 |
| 明细矩阵 | 行=`渠道[渠道]` | 总订单数、支付订单数、退款订单数、净支付金额、支付率、退款率、支付客单价 |

## 配色和排版

- 页面背景：`#F1F5F9`；卡片背景：白色；圆角 8 px。
- 主色：`#0891B2`；支付：`#0F766E`；退款：`#F59E0B`；取消：`#64748B`；SCD2：`#7C3AED`。
- 标题 20–24 pt，卡片值 24–30 pt，图表标题 12–14 pt。
- 金额趋势不要使用面积堆叠，以免退款被误解为支付金额的一部分。
- 保留统一的 32 px 页面边距和 24 px 主组件间距，全部对齐到 8 px 网格。

## SCD2 版本审计页

第三页已实现商品 ID 与“是否当前”下拉切片器，使用四张独立 KPI 卡展示商品数、版本记录数、当前版本数和调价商品数；左侧条形图只展示存在多个历史版本的商品，右侧明细表展示商品 ID、版本号、商品名称、品类名称、价格、生效时间、失效时间和当前标记。业务首页不暴露版本字段，审计页集中展示 SCD2 技术证据。

## 刷新与截图

1. 在项目目录运行 `docker compose up -d`，确认 ClickHouse 的 `localhost:8123` 可访问。
2. 确认本机安装 ClickHouse ODBC Unicode 驱动，打开 `电商实时数仓运营看板.pbip`。
3. 首次连接按 [Power BI 使用说明](PowerBI看板使用说明.md) 配置数据库认证，然后在 Power BI Desktop 中执行“刷新”。
4. 订单每日指标和商品版本历史的 Import 查询必须保留 `FINAL WHERE is_deleted = 0`；刷新后检查三页不存在空视觉或错误提示。

## 验收

1. 总订单数应大于等于支付和取消订单数。
2. 退款订单数不得大于支付订单数。
3. 退款金额不得大于支付金额。
4. 切片到任一渠道后，卡片值应等于 ClickHouse `ads_order_daily FINAL` 对应聚合。
5. 刷新后按业务键检查 `FINAL` 口径不重复；Power BI 查询必须保留 `FINAL WHERE is_deleted=0`。
